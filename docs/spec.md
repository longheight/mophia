# Mophia 仕様書 (2026-09-20版)

コンセプト資料 (`mophia_conc_01.pdf`, 2026-09-08) で「今後実装する内容・課題」として挙げられていた未決事項を中心に、稼働期限(2027年1月末)内に展示まで到達できることを最優先に、実現可能な仕様として決定する。

## 1. スコープの決定方針

このプロジェクトの最大のリスクは **「映像の動きから音楽そのものを自動生成する」機能が技術的に未検証・方針未定であること**。ここを開発期間の後半まで先送りにすると、1月末の展示に間に合わない可能性が高い。
したがって、**v1(展示版)のスコープを意図的に絞り込む**。自動作曲は展示後の発展課題とし、今回は「映像そのものを解析してUI/エフェクト/譜面を生成する」部分に集中する。

## 2. システム仕様

### 2.1 対応する映像

- **v1で対応**: 音源(BGM・環境音などプレイに使える音)が既に含まれている動画。実写・モーショングラフィックス問わず対応する。
- **v1で対応しない**: 無音、または音楽的に使えない音声のみの動画から音楽を自動生成する機能。技術検証にかかる工数が読めないため、v1のスコープからは外す。
- **フォールバック**: 送信された動画に使える音源がない場合、あらかじめ用意した汎用BGM数種の中から自動選択してゲームを生成する(処理を止めない)。
- **入力制約**: 最大尺 30秒(展示体験のテンポと解析時間を両立させるため。技術検証の結果次第で見直し)。ファイル形式はスマートフォンの標準出力形式(mp4/mov)を想定。

### 2.2 処理パイプライン

現行構成(OpenCV・SAM2・PyTorchによる映像/音楽解析 → Python で譜面データをJSON書き出し → Unity(C#)で読み込み・実行)を踏襲し、実写映像にも通用するよう解析ロジックを拡張する。

```
User(スマホ) → 動画アップロード(Web) → 解析サーバー(OpenCV/SAM2/PyTorch, Python)
            → 譜面JSON → Unity(C#) → 筐体ディスプレイ上で音楽ゲームとして実行
```

### 2.3 送信システム(動線)

- 筐体に **QRコード** を掲示し、来場者は自分のスマホで読み取って専用アップロードページを開く。
- アップロードページで動画を選択・送信 → サーバー側で解析開始。
- 処理中は筐体側に「解析中」の待機演出を表示する(体感待ち時間の緩和)。
- 目標処理時間: 送信から再生開始まで **60秒以内**(展示の回転率を確保するための目安。技術検証フェーズで実測して見直す)。

### 2.4 未決事項(今後の検証で確定させる)

- 実写映像に対する物体検出・輪郭抽出の精度チューニング
- 60秒以内の処理時間目標の実現可否
- 汎用BGMのラインナップ(何曲・どんな曲調を用意するか)

## 3. 筐体仕様

### 3.1 基本構造

コンセプト資料の透過ディスプレイ構造(前面ディスプレイ[カラーフィルター]・背面ディスプレイ・赤外線タッチスクリーンを柱で固定)を踏襲する。

### 3.2 サイズ・画面向き

- 一般的なアーケード音楽ゲーム筐体より小型のものを想定(白キューブ的なミニマルな展示空間に馴染むサイズ)。
- **画面向きは縦(ポートレート)を基本案とする**: 来場者が正面に立って両手で操作する体験、かつ省スペースの観点から。ただし10月の詳細設計フェーズで実機検証の上、最終決定する。
- 外形寸法は詳細設計フェーズ(Phase 1, 10月)で確定する。

### 3.3 スピーカー・QRスタンド

- スピーカーは筐体基部(ベース)に内蔵する方向で検討。
- QRコード掲示スタンドは筐体に一体化するか、独立スタンドにするかを詳細設計フェーズで決定する。

### 3.4 耐久性・安全性

- 不特定多数の来場者が繰り返しタッチする前提のため、配線の露出防止・パネルの固定強度・転倒防止(重心設計)を組み立て時に必ずチェックする。

### 3.5 製作方針

- 自作。既存プロトタイプ(2026年4月展示で使用したもの)の構造を流用・改修する。

## 5. 展示仕様

Mophiaは**2段階**で展示を行う。プレ展示で実来場者による検証を済ませてから、本展示に臨む構成とする。

### 5.1 プレ展示(12月中旬予定)

- **会場**: 九州大学大橋キャンパス内。学内施設のため会場予約のリードタイムが短く、外部ギャラリー予約が難航した場合のセーフティネットにもなる。
- **位置づけ**: Phase 3(統合・試験)の一環として、開発中の実機を実際の来場者に使ってもらい、フィードバックを本展示前の最終調整に反映する。これにより「稼働期限内に必ず来場者向け展示を行う」という要件を、本展示より前倒しで一度満たしておける。

### 5.2 本展示(1/17-1/25予定)

- **形式**: ホワイトキューブ的なミニマル展示(トーン・イメージとしてArtistCafe Fukuoka、NEORTのようなギャラリースペースを参照。ただし NEORT は東京拠点のため、運搬コストの観点から実際の候補地としては想定していない)。
- **体験内容**: 来場者が自分の持っている動画をMophia筐体に送信し、その場で生成されたインタラクティブな音楽ゲームをプレイする。
- **会場**: 未定。**筐体運搬の都合上、福岡市内を第一候補、広げても九州内**に絞って選定する。窓口(打診・交渉)は龍が担当する。
- **日程**: Phase 0で候補選定・打診を開始する(詳細はスケジュール参照)。ギャラリーは予約リードタイムが数週間〜数ヶ月かかる場合があるため、最優先で着手する。プレ展示より後、1月末の稼働期限内に実施する。

## 6. v1スコープ外(展示後の発展課題)

- 無音・非音楽的な動画からの自動作曲
- 処理時間のさらなる短縮・大量同時アクセス対応
- 30秒を超える尺への対応
