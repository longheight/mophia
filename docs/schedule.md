# Mophia 開発スケジュール (2026-09-20 策定, 2026-09-21 改訂)

## 前提条件

- 開発期間: 2026-09-20(土) 〜 2027-01-31(日) — 19週間
- 体制: 龍(ソフトウェア・全体統括、会場打診等の事務窓口)・井口(筐体)の2名。当面は**1人あたり週15時間**の稼働を目安に週次で進捗を確認する。
- **バースト対応**: 遅れが出た場合、龍は最大10h/日(週70h相当)まで稼働を引き上げられるが、**持続できるのは1週間程度**(連発不可)。週15h前提が崩れた場合の一時的な挽回策であり、恒常的な対策ではない。井口も同様に自身の上限を決めておく。
- 体調不良・不慮の事情による中断は完全には避けられない前提とし、都度ケアする(個別の代替要員は用意しない)。
- 会場(本展示)は未確定だが、**仮予算で並行して準備を進める**。会場確定を待たずに他タスクを進行させ、決まり次第該当箇所(予算表・告知物・搬入計画)を更新する。
- 稼働期限内に必ず来場者向け展示を実施する。**プレ展示(学内)→本展示(学外ギャラリー)の2段階**で行う([spec.md §5](spec.md#5-展示仕様)参照)。

## コンセプト資料の暫定スケジュールに対する見直し点

元の暫定スケジュール(9月〜2月、5ステップ)は以下の理由で1月末までに収まるよう再構成した。

1. **期限超過**: 元スケジュールは2月まで延びており、1月末の稼働期限を満たさない。
2. **展示そのものが工程に入っていない**: 「来場者想定のテスト」「バッファ・最終調整」はあるが、本番展示の期間が明示されていなかった。会場確保・告知にもリードタイムが必要。
3. **最大のリスク(音源自動生成)が後段に置かれていた**: 「音源の扱い」は方針未定の技術要素だが、スケジュール上は明示されておらず、後回しにすると1月末に間に合わなくなるリスクが高い。→ [spec.md](spec.md) の通りv1スコープから切り離すことで解消。
4. **会場確保が工程として存在しない**: 学外ギャラリー予約は外部依存でリードタイムが読めないため、最優先(Phase 0)で着手する必要がある。**加えて、外部会場が予定通り決まらない場合のセーフティネットとして、九州大学大橋キャンパス内でのプレ展示を統合・試験フェーズに組み込んだ**(展示要件を前倒しで一度満たしておける)。
5. **年末年始の稼働低下が考慮されていない**: 12月後半はバッファとして扱う。
6. **大きな締切しかなく、途中の進み具合が分からない**: 特にPhase1・Phase2(設計・システム関連)を週次の「第n提出」に分割し、各週でどの段階まで進めるべきかを明記した(下記)。
7. **統合デバッグの時間が実質的に不足していた**: 「統合・試験」と「プレ展示準備・実施」が同じ3週間に同居しており、プレ展示の準備・実施・撤収で1週間弱を消費すると、実質的な統合デバッグ時間が2週間を切る計算だった。→ Phase 2の最終週に「早期統合テスト」を前倒しで実施し、Phase 3を「統合・本格デバッグ(2週間)」と「プレ展示(1週間)」に明確に分割した。

## リスクと対応

| リスク | 対応 |
|---|---|
| 週15時間/人ペースでは実写対応・筐体制作が間に合わない | Phase 1・Phase 2を週次チェックポイントに分割し早期に遅れを検知。遅れていれば龍はバースト対応(最大10h/日×1週間程度)、または対応尺(30秒)をさらに短縮するなどスコープを削る |
| 学外ギャラリー予約が難航・遅延する | Phase 0で福岡市内(広げても九州内)の複数候補に同時打診。決まらなくても大橋キャンパスでのプレ展示により「稼働期限内に必ず展示を行う」要件は満たせる。仮予算のまま他タスクを並行進行し、会場決定を待たない |
| 実写映像解析の精度が想定より低い | 「対応できる映像の種類」を限定するガイド表示で運用回避(展示当日の受付で案内)。プレ展示でも精度を検証する |
| 統合デバッグの時間不足 | Phase 2最終週(11/22)に早期統合テストを実施し不具合を前倒しで発見。Phase 3を「統合・本格デバッグ(2週間)」と「プレ展示(1週間)」に分離し、デバッグ専用時間を確保 |
| 筐体の耐久性不足(公開展示で不特定多数が操作) | Phase 3aで必ず耐久・安全チェックを実施し、プレ展示でも実地検証した上で本展示前に補強する |
| 筐体の運搬(学外会場への搬入) | 本展示会場は福岡市内を第一候補、広げても九州内に限定して選定し、運搬負荷を抑える |
| 体調不良・不慮の事情による中断 | 個別の代替要員は用意しない前提。発生時はスケジュール全体を都度見直す |
