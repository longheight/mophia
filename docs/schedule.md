# Mophia 開発スケジュール (2026-09-20 策定)

## 前提条件

- 開発期間: 2026-09-20(土) 〜 2027-01-31(日) — 19週間
- 体制: 龍(ソフトウェア)・井口(筐体)の2名。当面は**1人あたり週15時間**の稼働を目安に週次で進捗を確認し、厳しければ稼働時間を増やす(この前提が崩れた場合、スケジュール全体の見直しが必要)。
- 稼働期限内に必ず来場者向け展示を実施する。

## コンセプト資料の暫定スケジュールに対する見直し点

元の暫定スケジュール(9月〜2月、5ステップ)は以下の理由で1月末までに収まるよう再構成した。

1. **期限超過**: 元スケジュールは2月まで延びており、1月末の稼働期限を満たさない。
2. **展示そのものが工程に入っていない**: 「来場者想定のテスト」「バッファ・最終調整」はあるが、本番展示の期間が明示されていなかった。会場確保・告知にもリードタイムが必要。
3. **最大のリスク(音源自動生成)が後段に置かれていた**: 「音源の扱い」は方針未定の技術要素だが、スケジュール上は明示されておらず、後回しにすると1月末に間に合わなくなるリスクが高い。→ [spec.md](spec.md) の通りv1スコープから切り離すことで解消。
4. **会場確保が工程として存在しない**: ギャラリー予約は外部依存でリードタイムが読めないため、最優先(Phase 0)で着手する必要がある。
5. **年末年始の稼働低下が考慮されていない**: 12月後半はバッファとして扱う。

## マイルストーン(要チェックポイント)

- **10/4**: 会場打診開始・筐体サイズ/画面向きの方向性決定
- **11/1**: 実写映像対応の技術検証完了。ここで進捗が厳しければ稼働時間を増やす判断をする第一関門。
- **11/1**: 会場決定(遅くともこの時点までに決めないと告知・準備期間が不足する)
- **11/29**: ソフト単体動作確認+筐体組み立て完了
- **12/20**: 統合完了・身内テストで一通り遊べる状態
- **1/16**: 展示準備完了
- **1/25まで**: 展示終了(1月末の稼働期限に対して5日のバッファを確保)

## リスクと対応

| リスク | 対応 |
|---|---|
| 週15時間ペースでは実写対応・筐体制作が間に合わない | 11/1時点で進捗確認し、遅れていれば稼働時間を増やす。または30秒制限をさらに短くするなどスコープを削る |
| ギャラリー予約が難航・遅延する | Phase 0で複数候補に同時打診し、11/1までに決定できるよう前倒しで動く |
| 実写映像解析の精度が想定より低い | 「対応できる映像の種類」を限定するガイド表示で運用回避(展示当日の受付で案内) |
| 筐体の耐久性不足(公開展示で不特定多数が操作) | Phase 3で必ず耐久・安全チェックを実施し、問題があれば展示前に補強する |
